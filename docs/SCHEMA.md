# Data Schema (SQLite)

This document defines the schema for the `user.db` SQLite database, which replaces file-based storage for user-generated data.

## 1. Core Entities

### `users`
Represents the system user. Currently single-user focused, but designed for future multi-user support.
- `id` (INTEGER PK): Auto-increment.
- `username` (TEXT UNIQUE): e.g., "default".
- `created_at` (DATETIME): UTC timestamp.

### `portfolios`
A user can have multiple portfolios (though UI currently supports one main view + snapshots).
- `id` (INTEGER PK): Auto-increment.
- `user_id` (INTEGER FK -> users.id): Owner.
- `name` (TEXT): Display name (e.g., "Main Portfolio").
- `currency` (TEXT): Base currency (default: "USD").
- `created_at` (DATETIME).

### `app_settings`
Key-value store for user preferences.
- `user_id` (INTEGER FK -> users.id).
- `key` (TEXT): e.g., "benchmark_ticker", "theme_mode".
- `value` (TEXT): JSON-serialized value.
- PRIMARY KEY (`user_id`, `key`).

## 2. Investment Data

### `trades`
Normalized ledger of transactions. Replaces `transactions.csv`.
- `id` (INTEGER PK).
- `portfolio_id` (INTEGER FK -> portfolios.id).
- `date` (DATE): Transaction date.
- `ticker` (TEXT).
- `action` (TEXT): BUY, SELL, SPLIT, DIVIDEND.
- `shares` (REAL): Quantity (positive for buy, negative for sell/transfer-out).
- `amount` (REAL): Net cash impact (negative for buy cost, positive for sell proceeds).
- `price` (REAL): Unit price (optional/derived).
- `fees` (REAL): Explicit fees (optional).
- `notes` (TEXT).

### `holdings_snapshots`
Point-in-time snapshots. Replaces `holdings.csv`.
- `id` (INTEGER PK).
- `portfolio_id` (INTEGER FK -> portfolios.id).
- `as_of_date` (DATE).
- `ticker` (TEXT).
- `shares` (REAL).
- `cost_basis` (REAL): Total cost basis for these shares (optional).

### `watchlist_items`
User's watched tickers. Replaces `watchlist.yml`.
- `id` (INTEGER PK).
- `user_id` (INTEGER FK -> users.id).
- `ticker` (TEXT).
- `created_at` (DATETIME).
- UNIQUE (`user_id`, `ticker`).

## 3. System & Run Metadata

### `runs`
Metadata for every computation run (`AppState` generation).
- `id` (TEXT PK): UUID string (e.g., "20231027-120000-abc12345").
- `portfolio_id` (INTEGER FK -> portfolios.id).
- `status` (TEXT): "running", "completed", "failed".
- `created_at` (DATETIME).
- `completed_at` (DATETIME, nullable).
- `input_hash` (TEXT): SHA256 of trades/holdings inputs.
- `config_hash` (TEXT): SHA256 of logic/config.
- `manifest_json` (TEXT): Full JSON dump of the run manifest.

### `artifacts`
References to outputs generated by a run.
- `id` (INTEGER PK).
- `run_id` (TEXT FK -> runs.id).
- `type` (TEXT): "html_report", "json_summary", "csv_export".
- `path` (TEXT): Relative path to storage (e.g., `data/exports/...`).
- `created_at` (DATETIME).

## 4. Indexes
- `idx_trades_portfolio_date`: `(portfolio_id, date)`
- `idx_watchlist_user`: `(user_id)`
- `idx_runs_created`: `(created_at DESC)`
